Translation

Runs Chrome's built-in Gemini Nano model locally – no API key, no server. It follows natural-dialogue instructions and reads up to eight earlier lines of this video. Needs Chrome 138+ with a capable GPU (or 16 GB RAM) and ~22 GB free disk; click Prepare model once to download it (~2 GB). Best output quality in English, Spanish and Japanese.

Depending on your Chrome version, Gemini Nano may require enabling chrome://flags/#prompt-api and restarting Chrome. Translation sends only text; the separate Prompt API image OCR engine below sends subtitle images. The #prompt-api-multimodal-input flag concerns image/audio input to the Prompt API. The experimental #on-device-model-speculative-decoding flag may also be available, but a speed improvement is not guaranteed. Flag names and availability vary by Chrome version.

When a video is found (usually before it starts) or paused, reads the tab title and page description once per page and looks up a short synopsis on Wikipedia (sends the title to wikipedia.org). The model uses it for names, relationships and terminology. Scripts or transcripts are never fetched.

Checks every 1 s and runs a tiny Gemini Nano prompt after at least 0.25 s idle to reduce GPU idle gaps between subtitles. Uses extra GPU power and may increase heat; cannot guarantee steady fan speed. Real translations interrupt it. Stops when the video is paused or the tab is hidden.

Python local bridge

Optional companion app: Chrome uses text-block detection and its existing local Paddle recognizer to select Chinese rows and avoid sending the same subtitle again. A changed or more complete reading triggers a new image; no Chinese reading returns empty evidence without contacting Python. Local Paddle assets are required. Chrome crops and stacks original-color Chinese rows with safety margins, excluding embedded English and unused width. Python no longer runs Paddle in default mode: it lightly sharpens the crop, then Qwen3-VL-2B transcribes and translates with context in one call, using a 230-token visual budget. Raw extension Paddle text is sent for logs/debug only, never as VLM prompt input or final transcription. Automatic cropping can still miss text; use debug to inspect the green crop regions. Confidence thresholds do not apply; centre, color and outline settings guide Chrome's row detection. Select Python for both OCR engine and Translator. Enable dialogue and story context above to reuse recent lines and title/description/synopsis. English translation targets only; other engines remain unchanged.

Loopback HTTP only. The token stays in this Chrome profile's local storage, not Chrome Sync. Run the companion app before testing. No images are sent to a cloud service.

OCR

Paddle selects and crops Chinese rows in original color and skips unchanged subtitles. Chrome's local image-capable Prompt API returns Chinese and English together, with output languages undeclared. Select Gemini Nano as translator to use that English directly without a second translation call. Requires local Paddle assets; no Python or cloud service.

Experimental: may be slower than PaddleOCR and may misread or invent text. Centred-only filtering is an instruction to the model, not a bounding-box check. Preprocessing, confidence thresholds and dictionary glyph correction do not apply. Keep the crop band tight around subtitles.

Inspect queries Chrome directly without downloading: default text, English/Chinese input and output, image input with English or Chinese output, and the exact OCR configuration. Shows raw availability values, native exception names/messages and sampling parameters. Availability is not proof of recognition accuracy. For Chrome's internal model diagnostics, open chrome://on-device-internals (if available in your build).
